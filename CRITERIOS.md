# Critérios de avaliação

O desafio será avaliado no nível esperado para estágio. Não esperamos domínio prévio de todas as ferramentas nem uma aplicação pronta para produção.

## Competências e pesos

| Competência               | Peso | Evidências observadas                                                                  |
| ------------------------- | ---: | -------------------------------------------------------------------------------------- |
| Fluxo principal           |  30% | API, listagem, busca, filtros, detalhes e registro de contato funcionando em conjunto  |
| Fundamentos técnicos      |  20% | Manipulação de dados, integração HTTP, validação, tratamento de erros e código correto |
| Raciocínio de produto     |  15% | Priorização, suposições explícitas e decisões coerentes com a rotina comercial         |
| Experiência de uso        |  15% | Clareza, feedback das ações, responsividade e acessibilidade básica                    |
| Qualidade e testes        |  10% | Teste relevante, nomes claros, organização proporcional e forma de validação           |
| Comunicação e aprendizado |  10% | `ENTREGA.md`, explicação das escolhas, transparência no uso de IA e domínio do código  |

## Escala

Cada competência recebe uma nota de 1 a 4.

| Nota | Significado                                                                             |
| ---: | --------------------------------------------------------------------------------------- |
|    1 | Não há evidência suficiente ou o comportamento central não funciona                     |
|    2 | Existe uma base parcial, mas seriam necessárias orientações frequentes                  |
|    3 | Resultado esperado para estágio: funciona, é compreensível e as decisões fazem sentido  |
|    4 | Acima do esperado para o nível, com boa autonomia e antecipação de problemas relevantes |

Entregas incompletas podem receber uma boa avaliação quando existe priorização consciente, qualidade no que foi concluído e clareza sobre os próximos passos.

## Não aumenta a nota por si só

- Quantidade de bibliotecas, arquivos ou padrões.
- Número de commits ou testes.
- Funcionalidades extras antes dos requisitos principais.
- Horas trabalhadas além do limite.
- Código gerado por IA que a pessoa não consegue explicar.
